# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A personal developer portfolio built from a Create React App template (React 18, react-router-dom v6, Tailwind CSS 3, GSAP for animations). It is being customized from the template into the owner's own portfolio.

## Commands

- `npm start` — dev server at http://localhost:3000 with hot reload
- `npm run build` — production build to `build/`
- `npm test` — Jest via react-scripts (watch mode). There are currently no test files; run a single test with `npm test -- <pattern>`.
- Linting runs through CRA's built-in ESLint (`react-app` config) during `start`/`build`; there is no separate lint script.

## Architecture

- **`src/Details.js` is the single source of content.** It imports every image asset and exports plain objects/arrays (`personalDetails`, `socialMediaUrl`, `workDetails`, `eduDetails`, `techStackDetails`, `projectDetails`, `contactDetails`). Pages and components import from it and only render. Content changes belong in `Details.js`, not in the page files.
- **Single scrolling page.** `src/App.js` routes `/` to `Pages/Home.js` and redirects every other path to `/`. `Home.js` renders the intro (`#about`) then `<About />` (about text, work with one-line `Summary`, education), `<Projects />` (`#projects`), `<Technologies />` (`#technologies`) and `<Contact />` (`#contact`); the files in `src/Pages/` are sections, not routes. The sticky header in `src/Components/Header.js` has a hardcoded `sections` list of anchor links, so a new section needs an `id` in its component, a place in `Home.js` and an entry in that list. `html { scroll-behavior: smooth }` in `index.css` animates the jumps; `scroll-mt-*` on sections keeps headings clear of the sticky header.
- **Tech stack** is data-driven: `techStackDetails` is an array of `{ heading, items: [{ name, img?, invert? }] }` sections rendered by `src/Pages/Technologies.js`. Icons come from `src/assets/techstack/` or icon CDNs via the `devicon()`, `iconifyLogo()` and `lobehub()` helpers in `Details.js`; items without `img` render as a letter tile; a group with `chips: true` (Tools) renders as plain outlined text chips instead of logos; `invert: true` inverts a logo in dark mode with a 180° hue rotation, so black logos turn white and dark-coloured ones (MySQL, Pandas) turn light while keeping roughly their hue. The section has one `h2` ("Technologies") and each group heading is a small uppercase `h3` label.
- Optional fields render only when set: project `image`/`previewLink`/`previewLabel`/`githubLink`/`highlight` (one-line result with a trend icon)/`details` (bullets behind a "Show details" toggle)/`imageInvert` (inverts a grayscale mockup in dark mode; other images are dimmed), work/education `Location`, and each `socialMediaUrl` entry (the header only renders twitter/linkdein/github).
- `About.js` maps over `workDetails`/`eduDetails` and `Projects.js` maps over `projectDetails` (rendered by `Components/Project.js`), so those lists can grow or shrink freely. Note the capitalized keys (`Position`, `Company`, …) for work/education entries and the misspelled `linkdein` key in `socialMediaUrl`, which `Header.js` depends on.
- **Assets:** images imported in JS go in `src/assets/` (bundled by webpack). Files that are linked by URL — e.g. the resume at `public/MoeYu_CV.pdf`, referenced as `personalDetails.resume = `${process.env.PUBLIC_URL}/MoeYu_CV.pdf`` — go in `public/`.
- **Styling:** Tailwind utilities plus a few custom classes defined with `@apply` in `src/index.css` (`max-width`, `section`, `bg-accent`, `text-accent`, `text-content`). The accent is a teal → cyan → sky gradient: `bg-accent`/`text-accent` define it, so change them there to restyle the whole site. Custom colors (`dark-heading`, `light-content`, `dark-card`, etc.) and the Poppins font are in `tailwind.config.js`. Dark mode uses Tailwind's `class` strategy (`darkMode: "class"`): an inline script in `public/index.html` adds `dark` to `<html>` before render (saved `localStorage.theme`, else the OS setting), and `Components/ThemeToggle.js` (sun/moon button in the header) flips it and saves the choice. The header has a scroll-spy: the section whose top has passed 40% of the screen gets `aria-current="location"`, which keeps its nav link in the gradient (desktop tabs also keep the underline). On phones the nav is a pop-over card (`.menu-card`) over a dimmed page; the ☰ icon draws into an × (`.menu-icon`). `public/index.html` must stay in Tailwind's `content` because `<body>` carries the page background classes.
- **Motion & icon rules:** timings are 150ms for colour/border changes, 250ms for movement (toggle knob, tab underline, arrow nudge), 75ms for a button press; the intro GSAP timeline is deliberately slow (2s per element, ~4s total, the owner prefers it) and is skipped under reduced motion. Gradient-on-hover text (`.hover-accent`, `.nav-link`, `.group-hover-accent`) always paints the gradient behind the letters and fades `color` to transparent, so it animates. UI icons are outline, 24-unit viewBox, stroke 1.75, 16px inline / 18px inside buttons; brand logos in the header stay filled.
- **Touch targets:** interactive elements are at least 44px tall on phones; small controls (36px social boxes, 32px theme switch) get an invisible larger hit area via `::before` (`.social-link`, `.touch-target`).
- **Hover rule:** text links (nav tabs, project links, contact phone/location) take the `.text-accent` gradient on hover; bordered controls (`.btn-secondary`, `.social-link`, theme toggle) get a teal-600 / dark teal-300 border. Keep new elements to this rule.
- **Blueprint background:** the `.blueprint` class in `index.css` draws a faint grid (25px / 125px) over the page colour with `background-attachment: fixed`. It is on `<body>`, the sticky header and the desktop footer so the lines line up across their edges; anything that needs to hide the grid (cards, `.btn-secondary`) gets a solid `bg-white dark:bg-…` fill. `Components/BlueprintDrawings.js` (mounted in `App.js`) adds four grid-coloured line drawings (gear, client→API→DB, neural net, chart) fixed in the side margins behind the page (`-z-10`, only from 1440px via a plain media query on `.bp-layer`, since a Tailwind screen would also change `.container` widths); `.bp-*` keyframes in `index.css` draw each one in, hold and fade on a 16s loop, static under reduced motion.
- **Tailwind gotchas (v3.0.24):** opacity modifiers must be on the default scale (`/10`, `/20`, `/30`… — `/15` fails to compile). `public/index.html` is in Tailwind's `content` because `<body>` carries the page background classes.
- **Experience/education timeline:** `About.js` wraps entries in `<ol className="timeline">` (vertical gradient line via `.timeline::before` in `index.css`); each `Components/Work.js` renders an `<li>` with a gradient dot positioned on that line.
- **Contact** (`Pages/Contact.js`) is built from `contactDetails`: a plain centered heading and subheading, no boxes: a large gradient email address (the mailto link, and the only gradient in the section) with a single "Copy Email" (clipboard) button, then the optional phone/location/availability details in one outlined panel below (same border and solid fill as `.btn-secondary`, cells split by dividers). Below `lg` the panel is a compact list (max-w-sm) of one-line icon + value rows with the text labels screen-reader-only; from `lg` it is three centred columns with labels. The section is at least one screen tall (`min-h-[calc(100vh-5rem)]`, content top-aligned so the gap above matches the other sections) so the Contact nav link never leaves Technologies showing above it. It ends with a "Back to top" link. Social links and the resume are deliberately *not* repeated there — they live in the header and the intro. Brand icons for the header are in `Components/SocialIcons.js`.
- **Animations:** `Home.js` uses a GSAP timeline on refs in a `useEffect` to slide in the heading lines and profile image (2s each with staggered delays). Under the name, `Components/RoleTyper.js` types out each entry of `personalDetails.roles` in a loop (cursor style `.type-cursor` in `index.css`); with OS reduced motion it shows all roles joined by `·` instead. The sentence below it is `personalDetails.intro`.
- **Type & spacing scale:** section titles use `.section-title` (24/30/36px); major sections start with `pt-16 md:pt-24`, sub-sections inside About with `pt-12 md:pt-16`. Work/education meta (company, location, dates) is 14px and stacks one per line on phones (dates get a calendar icon), one row from `md`. On phones the intro photo is a 192px rounded square crop. The intro role line is 20/24px medium gray so it supports the name. `personalDetails.about` splits into paragraphs on blank lines.
- **Page structure:** one `h1` (the intro name); section titles are `h2`, entries/project titles/extra tech groups are `h3`. The footer is fixed to the bottom of the screen from `lg` (desktop) up, and in normal flow after `<Contact />` on phones/tablets so it never covers content. Projects use a 2-column grid.
- **Icons:** `public/favicon-32.png`, `icon-192.png` and `apple-touch-icon.png` are a white "MY" monogram on the accent gradient (Poppins bold), linked from `public/index.html`.
- **Link previews:** `public/index.html` has description + Open Graph/Twitter tags pointing at `public/og-image.jpg` (1200x630, generated from the profile photo) by absolute URL `https://moyu1817.github.io/Portfolio/…`; regenerate the image if the name, roles or photo change.
- **Deployment:** GitHub Pages at https://moyu1817.github.io/Portfolio/ via `.github/workflows/deploy.yml` (builds on every push to `master`; copies `index.html` to `404.html` as the SPA fallback). Because the site lives under `/Portfolio/`, `package.json` sets `homepage`, the router uses `basename={process.env.PUBLIC_URL}`, and links to `public/` files must be prefixed with `process.env.PUBLIC_URL` (as `personalDetails.resume` is). `public/_redirects` is a leftover Netlify SPA fallback, unused on Pages.
